# 0002: Sovereign Content Filesystem Schema and Data-Store Contract

## Context and Problem Statement

Without a strict architectural contract, the authoring workspace (`editorial-content`) risks directory sprawl, inconsistent metadata schemas, and tool-specific syntax lock-in. Furthermore, allowing automated backend engines or AI agents to perform Git operations inside the content vault threatens to corrupt the writer's personal commit narrative and cause split-brain merge conflicts.

## Decision Drivers

* **Sovereignty & Portability:** Content must render natively in any standard Markdown editor (Obsidian, VS Code, Neovim) without requiring `editorial-engine` to run.
* **Deterministic Linter Ingestion:** Linters and search indexers require standardized, machine-readable YAML frontmatter to inspect lifecycle states, citations, and terminology.
* **Clean Boundary Enforcement:** Zero AI configuration directories (e.g., `.gemini/`, `.cursor/`) inside the content vault; directives are centralized in the engine and streamed via MCP.
* **Human-Exclusive Version Control:** Authors must retain complete, unpolluted control over their Git history.

## Considered Options

* **Option A: Deep Category Taxonomy & Unstructured Markdown:** Free-form folders by topic with no formal frontmatter schema.
* **Option B: Proprietary App Database / Headless CMS:** Replacing Markdown files with a headless CMS API or database.
* **Option C: Sovereign POSIX Data Vault with CommonMark & Enriched YAML (Chosen):** Minimal flat directory structure ($\le 2$ levels), structured CSL/BibTeX bibliographic frontmatter, repository-wide glossary, and strict human Git authority.

## Decision Outcome

Chosen option: **Option C**, ratified via [RFC 0002](../rfcs/0002_editorial_content_filesystem_contract.md).

### Key Architectural Directives:
1. **Directory Topography ($\le 2$ Levels):**
   * `drafts/`: Standalone posts (`YYYY-MM-DD_slug.md`) OR single-level series bundles (`YYYY-MM-DD_series-slug/part-N.md`).
   * `research/`: Extracted notes (`notes/*.md`), master citations (`bibliography.bib`), and controlled lexicon (`glossary.yaml`).
   * `assets/`: Media assets scoped per draft (`assets/<slug>/`).
2. **Bibliographic Schema:** Research note frontmatter enforces standard CSL/BibTeX fields (`citation_key`, structured `authors`, `publication`, `published_date`, `doi`) enabling deterministic AP, Chicago, and APA citation generation.
3. **Controlled Lexicon:** `research/glossary.yaml` defines canonical terminology and forbidden variants, enforced deterministically during Stage 6 line-editing.
4. **Git Sovereignty Policy:**
   * Human authors hold exclusive authority over Git commits in `editorial-content`.
   * AI agents and `editorial-engine` are **strictly prohibited** from executing Git commits in `editorial-content`; tool modifications are left unstaged in the working tree.
5. **No AI Directives in Vault:** `.gemini/` and prompt configuration files are prohibited in `editorial-content`.

### Consequences

* **Positive:**
  * Universal compatibility with all POSIX and Markdown tools; zero platform lock-in.
  * Deterministic citation and glossary linting prevents synonym drift and citation hallucination.
  * Human author's commit history remains pristine without automated noise.
* **Negative:**
  * Multi-part series require careful slug and frontmatter synchronization (`series.id`, `part`).
  * Authors must manually run Git commits for automated changes generated by the engine.
